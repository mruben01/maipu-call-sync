Quiero desarrollar una aplicación Android nativa como prueba de concepto (POC) llamada:

MAIPÚ CALL SYNC

CONTEXTO DEL PROYECTO

Estamos evaluando una solución corporativa para una fuerza comercial de aproximadamente 250 a 300 vendedores que utilizarán teléfonos Samsung Galaxy con líneas celulares corporativas.

NO queremos utilizar VoIP, SIP ni softphones.

Los vendedores deben continuar realizando y recibiendo llamadas celulares tradicionales utilizando la aplicación Teléfono nativa de Samsung y la línea SIM/eSIM corporativa.

Samsung Phone será responsable de realizar y grabar las llamadas.

Nuestra aplicación NO debe intentar grabar llamadas telefónicas.

Ya realizamos una prueba real en el siguiente dispositivo:

- Samsung Galaxy A04e
- Modelo SM-A042M
- Android 13
- One UI Core 5.0

En este dispositivo activamos la función nativa de Samsung:

Teléfono > Ajustes > Grabar llamadas > Grabar llamadas automáticamente.

Comprobamos manualmente que:

1. Las llamadas salientes se graban automáticamente.
2. Las llamadas entrantes se graban automáticamente.
3. Se escuchan ambas partes de la conversación.
4. Samsung genera archivos de audio .m4a.
5. Los archivos se almacenan en el dispositivo dentro de una ubicación equivalente a:

/Almacenamiento interno/Recordings/Call/

Un ejemplo REAL de nombre generado por Samsung es:

Grabación de llamada +543513993670_260918_090437.m4a

Por lo tanto, el nombre del archivo puede contener:

- número telefónico
- fecha
- hora

OBJETIVO DE ESTA POC

Quiero comprobar si una aplicación Android propia puede detectar y acceder programáticamente a las grabaciones creadas por Samsung Phone.

En esta primera versión NO desarrollar:

- grabación de llamadas
- VoIP
- softphone
- integración con TIMM
- integración con WISE
- Power BI
- transcripción
- inteligencia artificial
- eliminación automática de archivos
- backend complejo
- autenticación corporativa
- Samsung Knox

Primero debemos demostrar que Android permite que nuestra aplicación encuentre y lea los archivos generados por Samsung Phone.

TECNOLOGÍA

Crear una aplicación Android NATIVA.

Preferencias:

- Kotlin
- Android SDK
- Android Studio compatible project
- Gradle
- Material Design / Material 3
- minSdk razonable
- targetSdk actual compatible
- arquitectura simple y mantenible

No utilizar React Native, Flutter ni una PWA para esta POC.

La aplicación debe poder compilarse como APK instalable en el Samsung Galaxy A04e SM-A042M con Android 13.

PERMISOS

Implementar correctamente el modelo de permisos de Android 13.

Solicitar:

android.permission.READ_MEDIA_AUDIO

cuando corresponda.

NO solicitar MANAGE_EXTERNAL_STORAGE salvo que sea absolutamente imprescindible.

NO utilizar hacks, root, ADB permanente ni modificaciones del sistema operativo.

La solución debe funcionar en un teléfono corporativo Android normal.

ACCESO A LAS GRABACIONES

Utilizar prioritariamente APIs oficiales de Android.

Consultar:

MediaStore.Audio

para localizar archivos de audio creados por otras aplicaciones.

Buscar específicamente grabaciones:

- MIME type compatible con audio/mp4 o .m4a
- ubicadas dentro de Recordings/
- preferentemente Recordings/Call/

No depender exclusivamente de una ruta física hardcodeada.

Utilizar MediaStore y RELATIVE_PATH cuando Android lo permita.

Si Samsung registra estos archivos en MediaStore, mostrarlos.

Si no aparecen, informar claramente en la interfaz que MediaStore no está exponiendo las grabaciones.

No implementar soluciones inseguras para evitar las restricciones de Android.

INTERFAZ

Crear una interfaz muy sencilla.

Pantalla principal:

MAIPÚ CALL SYNC

Debajo mostrar:

Dispositivo:
Samsung Galaxy A04e

Android:
13

Estado del permiso de audio:
AUTORIZADO / NO AUTORIZADO

Luego:

GRABACIONES ENCONTRADAS

Mostrar contador:

Grabaciones encontradas: XX

Agregar botón:

BUSCAR GRABACIONES

Al presionarlo consultar nuevamente MediaStore.

LISTADO

Por cada grabación encontrada mostrar una Card.

Ejemplo:

--------------------------------

+54 351 3993670

18/09/2026 - 09:04

Duración: 00:47

Tamaño: 1.61 MB

Archivo:
Grabación de llamada +543513993670_260918_090437.m4a

Ruta:
Recordings/Call/

[ REPRODUCIR ]

--------------------------------

METADATA

Intentar obtener mediante MediaStore:

DISPLAY_NAME
DATE_ADDED
DATE_MODIFIED
SIZE
DURATION
MIME_TYPE
RELATIVE_PATH
CONTENT_URI

Nunca depender de DATA / filesystem absolute path si Android moderno no lo permite.

PARSER DEL NOMBRE

Crear una función independiente que intente interpretar nombres como:

Grabación de llamada +543513993670_260918_090437.m4a

Intentar extraer:

phoneNumber = +543513993670

date = 26/09/2018 o la interpretación correspondiente al patrón real

time = 09:04:37

IMPORTANTE:

No asumir silenciosamente el formato de fecha.

Documentar el patrón utilizado.

Si el parser no puede interpretar un nombre, la aplicación debe seguir funcionando y simplemente mostrar el nombre original.

REPRODUCCIÓN

Agregar un botón REPRODUCIR.

Utilizar Content URI obtenido desde MediaStore.

No copiar innecesariamente el archivo.

Si Android permite abrir el URI, reproducir el audio.

Esto es importante porque queremos demostrar no solamente que encontramos la metadata, sino que nuestra aplicación realmente puede LEER el contenido del archivo.

LOGS DE DIAGNÓSTICO

Agregar una sección opcional:

DIAGNÓSTICO

Mostrar:

- cantidad total de audios encontrados en MediaStore
- cantidad encontrada dentro de Recordings
- cantidad encontrada dentro de Recordings/Call
- permisos concedidos
- versión Android
- fabricante
- modelo
- errores de acceso

Esto será utilizado exclusivamente durante la POC.

PRUEBA DE ÉXITO

Consideraremos exitosa esta primera POC solamente si ocurre lo siguiente:

1. Instalamos la APK en nuestro Samsung Galaxy A04e.
2. Concedemos permiso de acceso a audio.
3. Realizamos una llamada celular normal desde Samsung Phone.
4. Samsung Phone genera automáticamente el archivo .m4a.
5. Abrimos Maipú Call Sync.
6. Presionamos BUSCAR GRABACIONES.
7. La nueva llamada aparece en la aplicación.
8. Podemos visualizar su metadata.
9. Podemos reproducir el archivo desde nuestra aplicación.

NO avanzar todavía con sincronización cloud hasta comprobar estos nueve puntos.

OBJETIVO FINAL DE ESTA ETAPA

La pregunta técnica que esta POC debe responder es solamente:

"¿Una aplicación Android corporativa propia puede detectar y leer automáticamente las grabaciones .m4a generadas por Samsung Phone en este Galaxy A04e con Android 13?"

No desarrollar funcionalidades adicionales hasta resolver esa pregunta.
